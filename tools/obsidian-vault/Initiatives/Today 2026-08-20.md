# Today 2026-08-20

## End-of-day checkpoint

Completed: architecture-first Git milestone, Identity phone OTP/Mini App core, Finance income/expense API core, panel authentication/card, standalone Finance dashboard, automated gates and browser QA.

Still blocks production: credential rotation, PostgreSQL migration/integration run, one-time panel handoff, live Finance data binding, hardening endpoints/workers and deployment. These remain P0/P1 in [[Knowledge/Open-Tails]].

Correction: no user-facing «Spacewhy ID» is being built. The existing panel at `drop.spacewhy.uz` is the entry surface; the Telegram bot/module only authenticates it, while every SpaceDrop is a separate entity.

## Definition of done for today

Не количество экранов, а один проверенный vertical slice:

`Telegram enrollment -> phone OTP -> panel session -> Finance card -> create income/expense -> dashboard reads it`.

## P0 — security and source of truth

1. Revoke the Telegram token exposed in conversation and issue a new token through BotFather.
2. Store the replacement only in the approved secret environment; create a distinct webhook secret.
3. Publish this architecture/specification commit before implementation.
4. Use current FastAPI `main` as the backend source of truth; do not restore obsolete Django notes.

## P1 — end-to-end MVP

1. Implement `identity` module: enrollment, verified contact binding, phone challenge, OTP outbox,
   verification, session/refresh/revoke and `me`.
2. Register isolated `spacewhy_auth_bot`; add webhook/handler contracts without embedding token.
3. Implement Finance persistence and migration: workspace, membership projection, accounts,
   categories, ledger, transfers, reversal/correction, idempotency, audit and outbox.
4. Implement Finance HTTP commands/queries and OpenAPI/error contracts.
5. Add backend unit/smoke/architecture/integration tests and run all applicable gates.
6. Build panel phone/OTP UI, authenticated shell and Finance SpaceDrop card.
7. Create clean `spacewhy-finance` project from UI kit and implement onboarding, dashboard,
   quick add and transaction list against typed API client.
8. Run lint/type/build plus desktop/mobile/Telegram viewport QA.

## P2 — hardening after vertical slice

1. Add reliable outbox worker delivery metrics, retry/DLQ state and reconciliation command.
2. Add shared Redis rate limits for horizontally scaled auth endpoints.
3. Add transfer, correction and archived reference UX.
4. Add route handoff from panel to Finance with one-time authorization code exchange.
5. Add deployment environment templates, CORS/trusted-host rules, webhook registration runbook and CI.

## P3 — later product increments

- budgets and savings goals;
- recurring entries/reminders;
- CSV import/export and receipt attachment/OCR;
- family/team workspaces and scoped permissions;
- bank/payment integrations and explicit FX provider;
- richer Telegram commands and notifications;
- advanced analytics and subscription packaging.

## Sequence and dependency notes

- Frontend cannot use real authentication until the bot token is rotated and the Identity API exists.
- Finance UI can proceed against typed fixtures after the API contract is frozen.
- Production deploy is not safe until secret rotation, migrations, public URLs, CORS, webhook secret,
  HTTPS and a real PostgreSQL integration run are complete.
- The standalone Finance repository has no assigned Git remote yet; local initialization is possible,
  but push requires a destination repository or permission to create one.
